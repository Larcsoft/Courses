Avant le module 1

Un espace de travail prêt en une séance

Avant de faire clignoter ta première LED, il faut des outils qui marchent. Ce module 0 t'aide à choisir ton logiciel, à l'installer, à brancher ta carte et à ranger ton travail, que tu codes en C/C++ ou en Python.

À la fin du module 0, tu auras

  • essayé un simulateur pour coder sans matériel ;
  • installé un ou deux logiciels, pas plus ;
  • vu ta carte apparaître sur l'ordinateur et ta LED clignoter ;
  • un dossier rangé pour tous les programmes de l'atelier ;
  • une fiche pour te dépanner seul quand ça bloque.

Ce qu'il te faut

  • un ordinateur Windows, macOS ou Linux ;
  • une carte Arduino Uno ou ESP32 DevKit, si tu en as une ;
  • un câble USB qui transporte des données ;
  • une LED et une résistance de 220 Ω (facultatif).

Sur Chromebook ou tablette, les simulateurs (étape 2) suffisent pour tout le niveau 1.

C/C++ ou Python ?

L'Arduino Uno se programme uniquement en C/C++. L'ESP32 accepte les deux. Python est plus simple pour débuter : pas de compilation, une commande tapée et la carte réagit aussitôt. C/C++ est plus rapide et dispose de plus de bibliothèques. L'atelier montre toujours les deux.

Étape 3 · Parcours C/C++

Installer l'IDE Arduino 2

L'IDE Arduino est le logiciel où tu écris le programme, le vérifies et l'envoies sur la carte. Le même logiciel sert pour l'Arduino Uno et pour l'ESP32 en C/C++.

Parcours Python

Tu codes l'ESP32 en Python ? Tu n'as pas besoin de l'IDE Arduino : passe directement à l'étape 4, puis à l'étape 5 (Thonny).

A · Installer le logiciel

  1. Va sur arduino.cc/en/software et télécharge Arduino IDE 2 pour ton système. Le site propose un don : clique sur Just download pour télécharger gratuitement.
  2. Lance l'installation et garde les choix proposés. Sous Windows, accepte l'installation des pilotes quand elle est demandée : ce sont eux qui permettent de voir la carte.
  3. Ouvre le logiciel. Pour le passer en français : File › Preferences › Language, choisis Français, puis OK.

B · Ajouter l'ESP32 (seulement si tu as un ESP32)

  1. Ouvre Fichier › Préférences.
  2. Dans URL de gestionnaire de cartes supplémentaires, colle cette adresse, puis OK :
    https://espressif.github.io/arduino-esp32/package_esp32_index.json
  3. Ouvre Outils › Carte › Gestionnaire de carte (ou l'icône carte dans la barre de gauche).
  4. Cherche esp32, choisis le paquet esp32 par Espressif Systems et clique sur Installer. Le téléchargement est gros : patiente quelques minutes.

Étape 4

Brancher sa carte

C'est l'étape où l'on bloque le plus souvent. Dans 9 cas sur 10, le problème vient du câble ou du pilote.

1 · Le bon câble

Certains câbles USB ne font que recharger : la carte s'allume, mais l'ordinateur ne la voit pas. Utilise un câble qui transporte des données, par exemple celui d'un téléphone avec lequel tu transfères des photos.

2 · Le pilote

Regarde la petite puce près de la prise USB de la carte. Son nom te dit quel pilote installer si la carte n'apparaît pas :

  • CP2102 ou CP210x : pilote Silicon Labs
  • CH340 ou CH341 : pilote WCH
  • Arduino Uno d'origine : pilote déjà installé avec l'IDE.

3 · Premier téléversement (IDE Arduino)

  1. Branche la carte, puis ouvre Outils › Carte et choisis Arduino Uno ou, pour l'ESP32, esp32 › ESP32 Dev Module.
  2. Ouvre Outils › Port et choisis le port qui apparaît quand tu branches la carte : COM3 sous Windows, /dev/cu.usbserial… sous macOS, /dev/ttyUSB0 sous Linux.
  3. Ouvre Fichier › Exemples › 01.Basics › Blink. Pour l'ESP32, remplace LED_BUILTIN par 2.
  4. Clique sur → Téléverser. Après « Téléversement terminé », la LED clignote.
  5. ESP32 seulement : si le message Connecting.... se répète puis échoue, maintiens le bouton BOOT de la carte appuyé jusqu'à ce que le pourcentage d'écriture s'affiche.

3 · Parcours Python

La carte se branche de la même façon. Le choix du port se fait dans Thonny, à l'étape 5.

Attention, piège

Sous Linux, si le port existe mais que l'envoi est refusé (« Permission denied »), ajoute ton compte au groupe dialout avec sudo usermod -a -G dialout $USER, puis ferme ta session et rouvre-la.

Étape 5 · Parcours Python

L'ESP32 en Python avec Thonny

Thonny est un éditeur Python très simple. Il sait installer MicroPython sur l'ESP32, puis te laisse parler à la carte ligne par ligne.

Parcours C/C++

Tu restes en C/C++ ? Cette étape est facultative. Tu peux la lire pour découvrir Python, puis passer à l'étape 6.

A · Installer Thonny et MicroPython

  1. Télécharge Thonny sur thonny.org et installe-le avec les choix proposés.
  2. Branche l'ESP32 (câble de données, pilote de l'étape 4 si besoin).
  3. Dans Thonny, ouvre Exécuter › Configurer l'interpréteur. Choisis MicroPython (ESP32) et le port de ta carte.
  4. Clique sur Installer ou mettre à jour MicroPython. Choisis la famille ESP32 et la variante Espressif · ESP32 / WROOM, puis Installer. Cette opération se fait une seule fois par carte.
  5. Ferme la fenêtre avec OK. Dans la Console en bas apparaît >>> : la carte t'écoute.

Labo · Parle à la carte comme dans Thonny

Tape les commandes une par une, dans l'ordre des boutons, et observe la LED. Essaie aussi de te tromper : les messages d'erreur sont là pour t'aider.

LED sur le GPIO 2

B · Faire démarrer ton programme tout seul

  1. Écris ton programme dans la zone d'édition en haut de Thonny (par exemple le Blink de l'étape 2).
  2. Clique sur ▶ Exécuter pour l'essayer. Le bouton rouge Stop l'arrête et rend la main.
  3. Quand il marche : Fichier › Enregistrer sous… › Appareil MicroPython, sous le nom main.py.
  4. Débranche puis rebranche la carte : le programme démarre seul, même sans ordinateur.
Attention, piège

Thonny et le moniteur série de l'IDE Arduino ne peuvent pas utiliser le même port en même temps. Si Thonny affiche « port occupé », ferme l'autre logiciel. Et pour revenir au C/C++ sur la même carte, il suffit de téléverser depuis l'IDE Arduino : MicroPython est remplacé.

Étape 7

Ça ne marche pas ? Dépanne-toi seul

Lis d'abord le message d'erreur : il dit presque toujours où chercher. Clique sur le symptôme qui ressemble au tien.

Aucun port n'apparaît quand je branche la carte
  1. Essaie un autre câble : beaucoup ne font que recharger.
  2. Essaie une autre prise USB de l'ordinateur, sans hub.
  3. Installe le pilote CP210x ou CH340 (étape 4), puis redémarre l'ordinateur.
Failed to connect to ESP32: Timed out waiting for packet header

L'ESP32 n'est pas entré en mode programmation. Relance le téléversement et maintiens le bouton BOOT pendant que Connecting.... s'affiche. Vérifie aussi que la carte choisie est ESP32 Dev Module.

avrdude: stk500_getsync(): not in sync (Uno)

L'IDE ne parle pas à la bonne carte. Vérifie Outils › Carte (Arduino Uno) et Outils › Port. Débranche aussi les fils des broches 0 et 1 : elles servent à l'USB pendant le téléversement.

'digitalwrite' was not declared in this scope

Une faute de frappe, souvent une majuscule : le C/C++ distingue digitalWrite et digitalwrite. Compare lettre par lettre avec l'exemple.

expected ';' before …

Il manque un point-virgule à la fin de la ligne précédente celle indiquée. Chaque instruction C/C++ finit par ;.

Je ne trouve pas ESP32 Dev Module dans la liste des cartes

Le paquet ESP32 n'est pas installé. Refais l'étape 3 B : l'adresse dans les Préférences, puis le paquet esp32 par Espressif Systems.

Le moniteur ou la console affiche des caractères bizarres

Dans l'IDE Arduino, la vitesse en bas du moniteur doit être la même que dans Serial.begin(). Dans Thonny, appuie sur Stop pour redémarrer la connexion. Voir le module 8 de l'atelier.

Could not enter REPL ou « port occupé » dans Thonny

Un programme tourne en boucle sur la carte, ou un autre logiciel utilise le port. Clique sur Stop (ou Ctrl + C dans la console) et ferme le moniteur série de l'IDE Arduino.

IndentationError: unexpected indent

En Python, les espaces au début des lignes comptent. Les lignes d'un même bloc doivent avoir exactement le même décalage : 4 espaces sous while True:.

NameError: name 'Pin' isn't defined

Il manque la ligne from machine import Pin en haut du programme. Même chose pour time : import time.

Mon programme Python ne démarre pas seul quand je rebranche la carte

Il est enregistré sur l'ordinateur, pas sur la carte. Fais Fichier › Enregistrer sous… › Appareil MicroPython, avec le nom exact main.py.

La carte redémarre sans arrêt ou chauffe

Débranche-la tout de suite. Vérifie qu'aucun fil ne relie directement 5 V (ou 3,3 V) à GND, et qu'aucun composant 5 V n'est branché sur une broche de l'ESP32.

La méthode du détective

Change une seule chose à la fois, puis réessaie. Si rien ne marche, reviens au programme Blink : s'il fonctionne, le problème est dans ton code ; sinon, il est dans le câble, le pilote ou les réglages.
